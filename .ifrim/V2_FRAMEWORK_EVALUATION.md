## Paperclip (paperclipai/paperclip)

- **Repository:** https://github.com/paperclipai/paperclip
- **Scop:** Plan de control open-source (server Node.js/Express + UI React) care modelează o „companie” de agenți AI: companie cu obiectiv, inițiative/goals, proiecte, organigramă cu roluri, titluri și linii de raportare (reportsTo), agenți-„angajați” cu buget lunar, issues/taskuri ierarhice cu dependențe (blockedByIssueIds), checkout atomic, heartbeat-uri și routines programate, guvernanță prin „Board” (aprobări pentru angajări și strategie, execution policies cu reviewer/approver), bugete și cost tracking, jurnal de activitate durabil, execution workspaces izolate (git worktrees, sandbox-uri cloud) și adaptoare către runtime-uri externe (Claude Code, Codex, Cursor, Gemini CLI, OpenCode, Pi, Hermes, Grok, Kimi, OpenClaw Gateway, process, http). Paperclip nu este runtime de agent; doar decide când, cum și cu ce context este invocat fiecare agent.
- **Versiune / dată:** Ultimul release: v2026.916.1 (21 sep 2026); anterior v2026.916.0 (16 sep 2026, 503 commituri, 49 migrații DB, sistemul Connections pentru credențiale), v2026.831.0 (31 aug 2026, Node 24.11+ obligatoriu). Ultimul commit pe master: 29 sep 2026; ~4.646 commituri. Versionare calendaristică (vYYYY.MDD.N).
- **Licență:** MIT. Fișierul LICENSE: Copyright (c) 2025 Paperclip AI; README: MIT © 2026 Paperclip Labs, Inc. Permite preluare de cod cu păstrarea notiței de copyright (de înregistrat în .ifrim/THIRD_PARTY_NOTICES.md dacă se copiază ceva).
- **Maturitate:** Proiect foarte popular și foarte activ (~94,4k stele, ~16k fork-uri, commituri zilnice, release-uri la 1–2 săptămâni cu sute de commituri), dar cu ritm mare de schimbări incompatibile (Node 24.11 obligatoriu, API de credențiale schimbat, zeci de migrații pe release). Documentație amplă (docs.paperclip.ing: ~21 pagini de adaptoare, API, CLI, plugin SDK) și specificație internă (doc/SPEC.md, doc/execution-semantics.md). Istoric de securitate încărcat: 10 GitHub Security Advisories în 2026, dintre care 5 critice. Pe master arată ca un produs matur ca funcționalitate, dar instabil ca suprafață de integrare.
- **Securitate:** Completări verificate: (a) În motorul ACP partajat, DEFAULT_ACP_ENGINE_PERMISSION_MODE = "approve-all". dangerouslySkipPermissions are implicit true, iar docs-ul claude_local justifică asta prin rularea headless (--print). Pentru Codex, DEFAULT_CODEX_LOCAL_BYPASS_APPROVALS_AND_SANDBOX = true: bypass-ul e activ dacă nu se configurează explicit un sandbox, o restricție de permisiuni sau networkAccess=false. E exact valoarea implicită pe care GHSA-gqqj-85qm-8qhf recomanda s-o treacă pe false (CVSS 8.7, afectat 2026.403.0, fără patch listat); pe master a rămas neschimbată. (b) Identificatori CVE: GHSA-68qg-g8mg-6pr7 = CVE-2026-41679 (CVSS 10.0, corectat în 2026.416.0). GHSA-x8hx-rhr2-9rf7 are CVSS 9.6 pe GitHub și a primit CVE-2026-77087 de la VulnCheck pe 21 aug 2026 (CVSS 9.4). VulnCheck indică 0.3.1 ca versiune corectată, dar aceasta nu se încadrează în schema calendaristică vYYYY.MDD.N. The Hacker News (5 aug 2026) notează că garda de hostname din v2026.416.0 acoperă implementările private. DEPLOYMENT-MODES.md de pe master nu documentează validarea Host în local_trusted, deci nu am putut confirma dacă release-urile curente au remedierea pentru local_trusted. (c) claude_local conține setup-token-runner, care rulează claude setup-token, preia din terminal token-ul OAuth de lungă durată și îl predă unui sink de credențiale; conform v2026.916.0, sistemul Connections gestionează abonamentele Claude/Codex prin sign-in. Asta întărește tensiunea cu regula Anthropic care interzice dezvoltatorilor să colecteze, să stocheze sau să intermedieze credențiale Claude.ai.
- **Windows:** Pe Windows nativ, suportul există parțial și neoficial; nu lipsește complet. Din v2026.722.0 (22 iul 2026), motorul ACPX încorporat nu mai învelește comenzile agenților locali într-un script Bash. Astfel, Claude, Codex, Gemini și adaptoarele ACP custom pornesc nativ pe Windows: shim-urile .cmd de npm/pnpm sunt preferate, iar un EPERM la symlink trece pe copiere. **Puncte forte**

- Model de domeniu complet pentru o „companie de agenți”: Company → Initiatives/Goals → Project → Issue → Sub-issue, organigramă cu CEO în vârf, delegare exclusiv prin taskuri și comentarii (fără canal separat de mesaje).
- Semantică de execuție foarte bine specificată: 7 statusuri (backlog, todo, in_progress, in_review, blocked, done, cancelled), două blocări distincte (checkoutRunId vs executionRunId), 409 pentru conflicte reale, atribuire atomică a unui singur owner.
- Contract de liveness: orice task non-terminal trebuie să aibă o cale de acțiune (run activ, wake în coadă, reviewer tipizat, monitor, owner uman, blocker sănătos sau acțiune de recuperare); altfel devine vizibil „stalled”.
- Recuperare explicită după crash/restart: un singur wake de recuperare pentru taskuri todo/in_progress orfane, apoi trecere în blocked cu acțiune de recuperare deținută de Board; rulările orfane sunt culese, cele din coadă reluate; fără auto-reasignare silențioasă.
- Distincție clară parentId (structură) vs blockedByIssueIds (dependență), cu wake automat issue_blockers_resolved; un blocker anulat rămâne nerezolvat până la eliminarea muchiei.
- Watchdog pentru rulări active tăcute (ok / suspicious / critical / snoozed) cu decizii ale Board-ului fără a crea taskuri noi.
- Guvernanță: Board poate pune pe pauză/relua/termina agenți și taskuri, poate suprascrie decizii; execution policies cu participanți tipizați (reviewer/approver) salvate tranzacțional împreună cu wake-ul.
- Bugete pe trei niveluri (vizibilitate, alertă soft la 80%, oprire hard cu auto-pauză și anularea muncii din coadă) și atribuire de cost pe companie/agent/proiect/goal/issue/provider/model.
- Adaptoare care pornesc CLI-urile oficiale locale (claude --print --output-format stream-json; codex exec --json) și pot folosi login-ul local pe abonament când nu există cheie API în mediu; reluare de sesiune între heartbeat-uri.
- Token de rulare scurt (JWT per run, injectat ca PAPERCLIP_API_KEY și refuzat din configurație), contract „no-remote-git” verificat static în CI, export/import de companie cu eliminarea secretelor, backup logic DB (pnpm db:backup).
- Itemul despre adaptoare trebuie corectat: motorul implicit nu mai este CLI-ul. Pentru claude_local și codex_local, motorul implicit este ACP, inclusiv pentru valorile vechi unset/„auto”. claude_local folosește @agentclientprotocol/claude-agent-acp (proiect comunitar, Apache-2.0, construit pe Claude Agent SDK), iar codex_local folosește @agentclientprotocol/codex-acp (comunitar, Apache-2.0, peste Codex app-server). Ambele sunt patch-uite în pnpm.patchedDependencies. Calea claude --print --output-format stream-json / codex exec --json este motorul CLI și rulează doar cu engine="cli" setat explicit; adaptorul nu schimbă automat motorul. Când nu există cheie API, se folosește în continuare login-ul local pe abonament (billingType subscription).

**Puncte slabe**

- Nu suportă oficial Windows nativ: INSTALLING.md acoperă doar macOS, Linux și WSL2; installer doar bash (install.sh), fără install.ps1; ghidurile de adaptoare vorbesc despre rularea „pe Mac”; modulele de quota folosesc Keychain (macOS) și comanda script (Linux/macOS).
- Valori implicite nesigure pentru politica Hub: claude_local are dangerouslySkipPermissions implicit true (trimite --dangerously-skip-permissions), iar codex_local trimite implicit --dangerously-bypass-approvals-and-sandbox; ambele sunt interzise explicit în adaptoarele V2.
- Mediul procesului copil este {...process.env, ...env}: o cheie ANTHROPIC_API_KEY sau OPENAI_API_KEY prezentă pe host comută silențios billingType de la subscription la api (inferență plătită).
- Ghidurile de onboarding („Hire Your First Agent”, „Agent Adapters”) și test-drive cer chei API (ANTHROPIC_API_KEY, OPENAI_API_KEY, OPENROUTER_API_KEY) și recomandă bugete în dolari; drumul pe abonament este secundar.
- Citește secrete ale vendorilor: quota.ts pentru Claude citește ~/.claude/.credentials.json (sau Keychain) și apelează api.anthropic.com/api/oauth/usage cu token-ul OAuth; quota.ts pentru Codex citește ~/.codex/auth.json și, ca fallback, apelează chatgpt.com/backend-api/wham/usage; codex-local copiază/sincronizează auth.json în CODEX_HOME per agent/companie; sistemul Connections stochează credențiale de abonament (setup-token, device login).
- Bugetele sunt în dolari; pentru Codex pe abonament costUsd este null, deci plafonul hard nu limitează efectiv consumul din cotele de abonament.
- Al doilea plan de control cu propria bază PostgreSQL (embedded-postgres patch-uit / Docker PG17 / Supabase), propriul sistem de aprobări, propriul jurnal: dublează exact nucleul V2 (misiuni, taskuri, aprobări, leases, evenimente, backup) și ar rupe principiul „o singură sursă autoritativă”.
- Telemetrie activă implicit (dezactivabilă prin PAPERCLIP_TELEMETRY_DISABLED=1 / DO_NOT_TRACK=1); integrări opționale OpenTelemetry/Sentry.
- Churn mare și schimbări incompatibile frecvente; suprafață vastă (62 connectors, chat Slack/Discord/Teams/Telegram, AgentMail, cloud sandboxes E2B/Cloudflare/Modal/Daytona) mult peste nevoile Hub.
- Formularea „mediul copilului este {...process.env, ...env}” e exactă doar pentru motorul CLI. Motorul implicit ACP filtrează mediul gazdei printr-un allowlist (ACPX_INHERITED_HOST_ENV_KEYS, LC_* și cheile de provider). Allowlist-ul de provider include însă explicit ANTHROPIC_API_KEY și ANTHROPIC_AUTH_TOKEN pentru Claude, respectiv OPENAI_API_KEY și CODEX_API_KEY pentru Codex. Așadar o cheie de pe host ajunge tot la agent, iar billingType se calculează din effectiveEnv (devine api dacă cheia există). Excepție: agenții codex_local noi sau actualizați salvează implicit un override OPENAI_API_KEY gol, care blochează moștenirea cheii de pe host. Pentru claude_local nu există o protecție echivalentă: ANTHROPIC_API_KEY nu e eliminat și nu apare niciun avertisment. Comutarea silențioasă pe facturare API rămâne deci reală pentru claude_local (pe ambele motoare) și pentru agenții codex_local vechi. O nuanță la quota Codex: citirea auth.json și apelul chatgpt.com/backend-api/wham/usage au loc doar pe calea de fallback, după ce eșuează account/rateLimits/read prin app-server.

**Componente reutilizabile**

- Contractul de liveness din doc/execution-semantics.md: orice task non-terminal trebuie să aibă o cale de acțiune numită; altfel devine vizibil „needs_attention/stalled” — de mapat pe mașina cu 12 stări a V2.
- Recuperarea muncii „stranded”: un singur wake de recuperare, apoi blocked cu acțiune de recuperare deținută de owner; queued reluat la pornire, running orfan cules — compatibil cu leases V2.
- Separarea checkoutRunId (proprietate) vs executionRunId (rulare vie), eliberate la stări terminale, cu 409 la conflict real.
- Distincția parentId vs blockedByIssueIds și wake-ul issue_blockers_resolved; regula că un blocker anulat rămâne nerezolvat până la eliminarea muchiei.
- Watchdog pentru output tăcut (ok/suspicious/critical/snoozed) cu decizii ale owner-ului (snooze, continue, dismissed_false_positive).
- Modelul de organigramă și roluri (agent cu rol, titlu, reportsTo, status active/paused/terminated) și delegarea exclusiv prin taskuri/comentarii — ca extensie opțională a modelului de misiuni V2.
- Bugete pe trei niveluri (vizibilitate, prag soft 80%, oprire hard cu auto-pauză și anularea cozii) — re-exprimate în V2 pe ferestre de cotă de abonament (account/rateLimits/read din codex app-server), nu în dolari.
- Execution policy cu participanți tipizați (reviewer/approver) salvați tranzacțional împreună cu wake-ul de review.
- Token de rulare scurt per run (în loc de chei lungi) pentru ca agenții să apeleze API-ul Hub.
- Contractul „no-remote-git” cu checker static în CI (fără git push din codul adaptoarelor).
- Injectarea de skills/instrucțiuni prin --add-dir și --append-system-prompt-file doar la sesiuni noi; reluare de sesiune cu verificarea cwd și refuzul directoarelor de sistem.
- Export/import de companie cu eliminarea secretelor (idee pentru export de misiuni V2).

Valoarea reală rămâne în tiparele de design. Încrederea în decizie rămâne ridicată, dar unele detalii tehnice ale intrării erau depășite.

## Hermes Agent (Nous Research)

- **Repository:** https://github.com/NousResearch/hermes-agent
- **Scop:** Agent AI autonom, auto-hostat (Python), construit în jurul unei bucle de învățare. Include memorie curatoriată de agent (MEMORY.md și USER.md, cu limită de caractere), creare și îmbunătățire autonomă de skill-uri în format SKILL.md, căutare FTS5 în sesiunile anterioare (~/.hermes/state.db) și modelarea utilizatorului (opțional prin Honcho, serviciu cloud). Mai oferă un gateway de mesagerie (Telegram, Discord, Slack, WhatsApp, Signal, Email, Home Assistant), cron, subagenți, server ACP pentru editoare, desktop app și web dashboard. Poate rula cu mai mulți furnizori de modele: Nous Portal (recomandat de proiect), OpenRouter, OpenAI, Anthropic, OpenAI Codex prin OAuth ChatGPT, GitHub Copilot, xAI, modele locale și endpoint-uri custom.

- **Maturitate:** Proiectul este foarte popular și foarte activ. Pagina GitHub citită arăta aproximativ 250k stele, 53k fork-uri, 46k commit-uri și peste 5.000 de issues/PR-uri deschise. Cifrele provin din rezumatul automat al paginii, deci sunt aproximative. Release-urile vin foarte des, iar un singur patch consolidează sute de PR-uri (v0.21.4 a inclus circa 1.800). - **Securitate:** Modelul declarat de proiect (pagina Security Policy) spune că singura graniță reală de securitate este izolarea la nivel de OS. Aprobările și redactarea sunt doar euristici. Aprobarea comenzilor periculoase are trei moduri: smart (evaluare de risc făcută de LLM), manual și off. Există și modul YOLO, limitat doar de un blocklist minim. În backend-urile container (Docker, Modal, Daytona, Vercel, Singularity), verificările de comenzi sunt sărite complet. Alte protecții documentate: env filtrat implicit, directoarele ~/.ssh și ~/.aws protejate la scriere, protecție SSRF, fișiere de credențiale cu mod 0600, scanare de injection pe context files, memorie și skills, plus Tirith pentru detecție înainte de execuție. v0.21.0 a introdus aprobare obligatorie înainte ca agentul să-și modifice propriile instrucțiuni. Riscuri pentru Hub: (1) Hermes citește și stochează tokenuri de abonament (credential store Claude Code, ~/.codex/auth.json). Asta încalcă regula Hub care interzice citirea acestor fișiere și, pentru Anthropic, pagina Legal and compliance. (2) Instalarea este pipe-to-shell de pe un domeniu terț și aduce Python, uv, Node, ripgrep și FFmpeg. (3) Hub-urile comunitare de skill-uri sunt o suprafață de supply-chain; forțarea instalării prin --force este posibilă pentru constatările care nu sunt periculoase. (4) Gateway-ul de mesagerie și auto-start-ul prin Scheduled Tasks creează efecte externe și configurație persistentă, pe care Hub-ul le permite doar cu aprobare explicită. (5) tools/skills_guard.py nu a putut fi citit (HTTP 429), așa că detaliile scanării provin doar din documentație.

Nu funcționează nativ: panoul de terminal din dashboard (necesită ConPTY/pywinpty), mesageria Matrix criptată, iar pe ARM64 lipsesc unele SDK-uri (mem0, google-chat, Faster-Whisper). Pentru fork POSIX și file watchers, documentația recomandă WSL2. Nu a fost verificat local: nu s-a instalat nimic, conform regulilor BUILD_SAFE.

În core, fastapi (>=0.104.0,<1), uvicorn (>=0.31.0,<1) și urllib3 au intervale; extra-ul web fixează fastapi==0.133.1 și uvicorn==0.41.0. anthropic==0.87.0 apare doar în extra-ul anthropic. pyproject definește peste 50 de extras, între care honcho, cron, pty, vision, termux-all și all.
- **Facturare:** Formularea că niciun furnizor documentat nu este compatibil este prea absolută. Cu runtime-ul codex_app_server, turele principale trec prin clientul oficial Codex și abonamentul ChatGPT. Totuși, task-urile auxiliare cer tokenuri ChatGPT stocate de Hermes, iar eligibilitatea nu este documentată. Rezultatul rămâne ELIGIBILITY_UNKNOWN și contrar regulii Hub despre tokenuri. apiBillingRisk high rămâne corect pentru căile implicite: OAuth Anthropic doar pe usage credits, chei API, Nous Portal (pagina citită nu dă preț și nu menționează free tier), OpenRouter și xAI. Modul implicit de aprobare smart face câte un apel LLM auxiliar pentru fiecare comandă riscantă.
- **Complexitate operațională:** Ridicată. Hermes este un al doilea runtime complet, cu stare proprie: state.db, memories, skills, pending, auth.json, config.yaml, logs și curator backups. Are procese de fundal (gateway, cron, curator, desktop maintenance), iar auto-start-ul se face prin Scheduled Tasks. Ar trebui sincronizată stare între două control plane-uri, iar ritmul de upgrade este foarte rapid și a produs regresii (corupere DB în v0.21.0). Pentru Hub, integrarea ar însemna să guvernăm un proces Python terț cu propriile aprobări, credențiale și fluxuri externe. Asta este incompatibil cu BUILD_SAFE și cu regula Hub care cere un singur plan canonic.
- **Suprapunere nativă OpenAI:** Codex local memories: fișiere în ~/.codex/memories/, generate asincron din chat-uri eligibile, cu redactare de secrete, controlul /memories și un prag de rate-limit. Feature-ul memories apare activ local în codex features list. Codex skills respectă standardul deschis Agent Skills, cu locații în .agents/skills, ~/.agents/skills, /etc/codex/skills și skill-urile de sistem. Mai există $skill-creator, agents/openai.yaml, dezactivare din config.toml și detectarea automată a schimbărilor. Alte suprapuneri: AGENTS.md ca instrucțiuni persistente; subagenți (multi_agent și noul view /agents din CLI); automatizări locale (in_app_local_automation) și MCP Events pentru automatizări din plugin-uri; plugin-uri; remote-control și acces de pe telefon; memoria ChatGPT și skills în ChatGPT. Echivalentul OpenAI cel mai apropiat de un agent „always-on” proactiv este dots, dar este disponibil doar pe Pro și Business Premium, deci ELIGIBILITY_UNKNOWN pentru planul „prolite”, neverificat. Aceste funcții acoperă memoria per proiect, skill-urile procedurale, subagenții și automatizările, toate prin abonamentul ChatGPT și clientul oficial.
- **Suprapunere nativă Anthropic:** Formularea fără extra usage este prea absolută. Funcțiile native consumă alocarea comună a planului Max (claude.ai, Claude Code, Desktop). Pe Pro, Max 5x și Max 20x, usage credits se activează opt-in din Settings > Usage, se facturează la tarife API standard și pot avea auto-reload. Prin urmare, apiBillingRisk corect pentru aceste suprafețe este low, nu none. Restul este confirmat: auto memory (200 de linii sau 25KB, tipurile user, feedback, project și reference, câmpul modified, memorie per subagent), /doctor prompt-audit, /import și skill-urile sincronizate în ~/.claude/skills/synced. În plus, Claude Code citește nativ AGENTS.md începând cu v2.1.277.
- **Valoare unică:** După ce scădem suprapunerile native și ce are deja Hub-ul (memory_items cu FTS5 unicode61 remove_diacritics, 7 scopes, versiuni cu supersedes_id și OUTDATED, detectare de contradicții, respingerea conținutului care seamănă cu secrete, intrări ale agentului doar ASSUMPTION/HYPOTHESIS până la promovare, skill_proposals aprobate de om), rămân puține lucruri. Valoarea unică reală este de design, nu de runtime: (1) curatorul determinist de ciclu de viață (usage tracking, stale/archive, protecție pinned, ledger cu rollback), (2) linterul „lessons, not logs” pentru skill-uri, (3) scanarea injection/exfiltration pe conținutul injectat în prompt, (4) bugetul fix cu snapshot înghețat, (5) nivelurile de încredere și scanarea la instalarea skill-urilor din surse externe. Gateway-ul de mesagerie (Telegram, WhatsApp, Signal) și generarea de traiectorii pentru antrenare sunt unice, dar nu sunt dorite: implică mesaje externe și date trimise în afară.
- **Decizie:** **REFERENCE** — Hermes trebuie folosit doar ca referință de design pentru bucla memorie/skills, fără instalare, integrare sau rulare. Pentru runtime-ul său, statusul de capability ar fi BLOCKED, cu apiBillingRisk high, programmaticIntegration NONE în politica Hub, executionSurface none și hubDecision REFERENCE. Motivele: (1) Nu există cale de inferență compatibilă cu INCLUDED_SUBSCRIPTION_ONLY. OAuth pe Max consumă explicit extra usage, cheile API și Nous Portal sunt plătite, iar providerul openai-codex ocolește clientul oficial, are eligibilitate nedocumentată și cere tokenurile ChatGPT. (2) Folosirea credential store-ului Claude Code de către un produs terț contrazice pagina oficială Legal and compliance a Claude Code și regula Hub de a nu citi credențiale. (3) Memoria și skill-urile sunt deja rezolvate mai bine de standarde și funcții native: Agent Skills (agentskills.io) este citit nativ de Claude Code și de Codex, auto memory din Claude Code și local memories din Codex acoperă memoria per client, iar Hub V2 are deja memorie canonică, independentă de furnizor, cu FTS5, scopes, versiuni și aprobare umană. Formatul skill-urilor scrise de Hermes este chiar mai puțin portabil decât standardul, deoarece încalcă regulile pentru metadata și câmpurile top-level. (4) Hermes ar deveni un al doilea control plane, cu risc operațional ridicat. Ce merită preluat, ca idei reimplementate în Node în domeniul Hub și cu mențiune MIT dacă se adaptează cod: curatorul determinist cu ledger și rollback, linterul de skill-uri, scanarea injection/exfiltration și snapshot-ul de memorie cu buget fix. Încrederea în decizie este mare, fiind susținută de documentația oficială Hermes și Anthropic. Câteva valori numerice (stele, număr de PR-uri) vin din rezumate automate ale paginilor și sunt aproximative.
- **Ownership propus:** Nimic din Hermes nu intră în proiect: nu se instalează, nu se clonează și nu se copiază cod. Hub V2 (hub.local) rămâne proprietarul canonic al memoriei (v2/server/domain/memory.mjs) și al registrului de skill-uri, cu Catalin ca aprobator. Propunerea este ca registrul de skill-uri să fie exportat în format Agent Skills strict (doar name, description, license, compatibility, metadata cu valori string sub un prefix precum ifrim-*, allowed-tools), validat cu skills-ref. Scrierea în .claude/skills/ și .agents/skills/ se face doar cu aprobare explicită, ca Claude Code și Codex să le consume nativ. Auto memory din Claude Code și local memories din Codex rămân MIRROR_STATE, sincronizate read-only prin coloanele deja existente source_kind și sync_direction. Tiparele de curator, linter și scanare se implementează ca REIMPLEMENT în domeniul Hub de către workerul desemnat (Codex coordonator sau Claude specialist), după aprobarea lui Catalin. Pentru ideile adaptate se adaugă mențiunea MIT în .ifrim/THIRD_PARTY_NOTICES.md.

**Puncte forte**

- Bucla de învățare este documentată în detaliu. Memoria are buget fix de caractere (MEMORY.md 2.200, USER.md 1.375), acțiuni add/replace/remove și un snapshot înghețat la începutul sesiunii, care păstrează prefix cache-ul.
- Intrările de memorie sunt scanate pentru injection și exfiltration înainte de a fi acceptate, deoarece ajung în system prompt. Există și memory.write_approval.
- Hermes citește skill-uri în format SKILL.md (standardul agentskills.io), cu progressive disclosure pe trei niveluri: skills_list, skill_view și skill_view(path). Scanează și .agents/skills/, adică aceeași locație folosită de Codex.
- Skill-urile scrise de agent trec prin guvernanță. skills.write_approval pune modificările în staging (~/.hermes/pending/skills/), iar comenzile /skills diff și /skills approve permit revizuirea. Un linter consultativ semnalează skill-urile scrise ca jurnal de incident, prea multe referințe (peste 60 de fișiere) sau un corp prea mare (peste ~24k caractere).
- Curatorul are un ciclu de viață bine gândit pentru skill-urile create de agent. Urmărește utilizarea, marchează ca stale după 14 zile și arhivează după 30 de zile, fără ștergere. Protejează skill-urile pinned și pe cele folosite de cron, face snapshot înainte de consolidare și ține un ledger append-only cu rollback per intrare și --dry-run.
- Skill-urile instalate din hub-uri sunt scanate pentru exfiltration, prompt injection, comenzi distructive și semnale de supply-chain. Sursele au niveluri de încredere: builtin/official, trusted și community.
- Importul din Claude Code și Codex (CLAUDE.md/AGENTS.md, MCP, skills) arată planul înainte de aplicare și are --dry-run. Fișierele de credențiale nu sunt citite, iar variabilele MCP cu nume de secret sunt eliminate.
- Windows nativ are status GA, cu shell prin Git Bash (aceeași abordare ca la Claude Code). Există un server ACP (hermes acp) pentru Zed, VS Code și JetBrains.
- Licența MIT permite adaptarea ideilor și a codului.

**Puncte slabe**

- Facturarea este incompatibilă cu INCLUDED_SUBSCRIPTION_ONLY. Cu OAuth Anthropic, un plan Claude Max plătește doar din extra usage, iar alocarea inclusă în plan rămâne neatinsă, conform docs Hermes. Varianta ANTHROPIC_API_KEY înseamnă facturare API. Nous Portal și OpenRouter sunt servicii plătite noi.
- Providerul OpenAI Codex nu folosește clientul oficial. Apelează direct backend-ul chatgpt.com cu OAuth ChatGPT, își păstrează tokenurile în ~/.hermes/auth.json și poate importa ~/.codex/auth.json. Documentația OpenAI citită nu spune dacă sunt permise harness-uri terțe, iar Hermes nu documentează cum se consumă limitele planului.
- Providerul Anthropic folosește direct credential store-ul Claude Code (preia autentificarea deja făcută în Claude Code). Pagina Legal and compliance a Claude Code interzice dezvoltatorilor terți să colecteze sau să intermedieze credențiale Claude.ai și să ruteze cereri prin credențiale Free/Pro/Max.
- Skill-urile scrise de Hermes nu respectă strict specificația Agent Skills. Folosesc câmpuri top-level (version, platforms, required_environment_variables) și metadata.hermes imbricat (liste și obiecte), deși specificația cere ca metadata să fie map string→string. Validatorul oficial skills-ref respinge câmpurile top-level neașteptate.
- Hermes ar fi un al doilea control plane, cu stare proprie (state.db, memories, skills, auth.json, config.yaml, cron, gateway). Asta contrazice principiul unui singur plan canonic al Hub-ului.
- Stack-ul diferă de Hub (Python 3.11–3.14, uv, pachete pinned față de Node 24). Instalarea recomandată este pipe-to-shell: iex (irm https://hermes-agent.nousresearch.com/install.ps1).
- Ritmul de schimbare este foarte mare și au existat regresii grave de date (coruperea session store în v0.21.0).
- Documentația se contrazice: README spune că session search folosește sumarizare LLM, iar pagina Memory spune că rezultatele sunt mesajele brute, fără sumarizare.
- Skill-ul inclus claude-code recomandă --dangerously-skip-permissions, --bare și --max-budget-usd, adică exact flag-urile interzise în adaptorul V2. Mai afirmă greșit că ANTHROPIC_API_KEY ar folosi facturarea abonamentului.
- Unele componente trimit date private către servicii externe: providerii de memorie Honcho, RetainDB și Memori (cloud, plătiți), plus consolidarea curatorului, care face 50–100 de apeluri LLM auxiliare per rulare când este activată.

**Componente reutilizabile**

- Tipar (doar referință, fără cod): memorie delimitată cu buget fix de caractere și snapshot înghețat, injectat la startul sesiunii, apoi neschimbat până la sesiunea următoare (tools/memory_tool.py, pagina Memory). **Puncte forte**

- Acoperire foarte largă de canale de mesagerie într-un singur gateway, cu pairing implicit pentru expeditori necunoscuți și allowlist (`openclaw message send` acoperă WhatsApp, Telegram, Slack, Discord, Signal, iMessage, Teams, Matrix, Google Chat și Mattermost).
- Poate rula clienții oficiali: Codex prin app-server-ul oficial și Claude prin binarul Claude Code instalat (`claude -p --output-format stream-json`), fără să citească tokenurile native pe ruta Claude CLI.
- Skills în format SKILL.md (compatibil conceptual cu skills din Claude/Codex), cu precedență, gating și registrul ClawHub care afișează scanări VirusTotal/ClawScan.
- Scheduler (automations/cron) cu istoric de rulări, joburi one-shot și livrare pe canale; audit bazat numai pe metadate, cu „decision receipts”.
- Licență MIT, documentație foarte detaliată livrată în pachet, protocol Gateway documentat (WebSocket + RPC) și pachete client stabile.
- Separă explicit în documentație facturarea prin abonament de facturarea API și poate păstra OPENAI_API_KEY/CODEX_API_KEY în afara procesului copil app-server când e selectat un profil de abonament.
- Nuanțe. (1) Pe ruta claude-cli, OpenClaw nu citește tokenurile native, dar poate injecta prin file descriptor tokenuri de abonament salvate în propriul store. Afirmația e deci corectă doar pentru login-ul nativ. (2) Scanările VirusTotal și LLM din ClawHub depind de chei și configurări activate de operator, conform THREAT-MODEL-ATLAS. Nu sunt o garanție implicită.

**Puncte slabe**

- Devine un al doilea orchestrator: are propriile sesiuni, agenți, workboard/taskflow, standing orders, memorie și cron, deci dublează planul de control al Hub-ului. REBUILD_DECISIONS l-a identificat drept sursa majorității blocajelor HUB-018.
- Pe Windows e lent și fragil: startup-ul durează minute (issue-urile P0/P1 deschise și evidența V1), sessions.create a durat între 80 s și 30 min, iar Gateway-ul a pornit în rafală 23 de copii codex app-server cu 23 de console OpenConsole vizibile (spawnOptions fără windowsHide pe workerul SQLite).

## Agent Zero (agent0ai/agent-zero)

- **Repository:** https://github.com/agent0ai/agent-zero
- **Scop:** Framework open-source de agent autonom, scris în Python. Îi dă agentului un calculator Linux complet în Docker: desktop XFCE (Xpra), browser cu adnotare DOM, terminal și execuție de cod, cowork pe documente (Markdown, LibreOffice), proiecte izolate, memorie, skills, pluginuri, MCP și A2A, plus subagenți. Puntea A0 CLI îl leagă de mașina gazdă: fișiere, shell, browserul gazdei și computer use pe desktopul gazdei (beta). Vechiul URL github.com/frdel/agent-zero afișează același repo agent0ai.
- **Versiune / dată:** Ultima lansare este v2.13, publicată pe 2026-09-23 (GitHub API). Lansările anterioare: v2.12 pe 09.09, v2.11 pe 27.08, v2.10 pe 19.08, v2.9 pe 12.08.2026. Ultimul push pe main este din 2026-09-23. A0 Launcher este la v1.8. Repo-ul a fost creat pe 2024-06-10.
- **Licență:** MIT. Textul LICENSE are antetul „Copyright (c) 2025 Agent Zero, s.r.o”; din cauza liniilor suplimentare de contact, GitHub raportează spdx NOASSERTION. Pluginul _orchestrator are propriul LICENSE MIT. a0-launcher, a0-install, a0-connector și space-agent sunt tot MIT.
- **Maturitate:** Corecție: schimbarea transportului implicit de model (LiteLLM trece la Chat Completions; Codex/ChatGPT și xAI OAuth rămân pe Responses) a venit în v2.11 (2026-08-27), nu în v2.12. v2.12 (2026-09-09) a adus întărirea transportului connectorului și remedieri de securitate: path traversal pe media WhatsApp și bypass de autentificare pe webhook-ul Telegram. Pe lângă SECURITY.md absent (404 în rădăcină, în .github/, în docs/ și în repo-ul de organizație agent0ai/.github), pagina Security arată că nu există politică de securitate și nicio advisory GHSA publicată. Repo-ul are totuși un registru intern, security-review/LEDGER.md (de exemplu WA-001, revizuit 2026-09-09).
- **Securitate:** Confirmat și precizat în cod. Client_id-ul implicit al pluginului _oauth este identic cu cel din sursa oficială openai/codex (codex-rs/login/src/auth/manager.rs). Scope-urile cerute copiază login-ul Codex CLI și includ api.connectors.read și api.connectors.invoke, deci permisiunile tokenului depășesc inferența. La fel sunt copiate parametrul codex_cli_simplified_flow, originator codex_cli_rs și endpointul deviceauth/usercode. Pe cererile Responses, antetul version trimite 0.155.1 (sau rezultatul `codex --version` local). User-Agent „codex-cli” apare doar pe endpointul de usage; refresh-ul de token folosește User-Agent agent-zero/<versiune>. Tokenurile stau în /a0/usr/plugins/_oauth/codex/auth.json, iar căile auth.json ale Codex CLI sunt refuzate. Proxy-ul OpenAI-compatibil /oauth/codex/v1 ascultă doar pe loopback, dar are require_proxy_token: false implicit. Lanțul de aprovizionare mai are un punct: A0 Launcher (Electron 42) încarcă UI-ul (content.json) din ultimul GitHub Release și se actualizează prin electron-updater. Registrul de securitate confirmă că procesul framework rulează ca UID 0 în container.
- **Windows:** Da, indirect. Nucleul rulează doar în Docker (Docker Desktop cu WSL2 pe Windows). A0 Launcher v1.8 are build-uri Windows x64 și ARM64. A0 CLI se instalează prin PowerShell (uv cu CPython 3.12 gestionat) și include un backend de computer use pentru Windows bazat pe UI Automation. Bring Your Own Browser detectează Chrome, Edge, Brave, Opera și Vivaldi pe Windows. requirements.txt include pywinpty pentru win32, dar documentația cere Docker pentru rulare. Pe această mașină există Docker 29.4.3 și WSL; nu am pornit nimic.
- **Dependențe:** Imaginea Docker agent0ai/agent-zero (nginx, supervisor, SearXNG, SSH, XFCE+Xpra, LibreOffice, Chromium prin patchright). Python: litellm 1.88.1, openai 2.41.1, patchright 1.61.2, fastmcp 3.2.4, mcp 1.27.0, fasta2a 0.5.0, faiss-cpu, sentence-transformers, langchain-core/community, unstructured[all-docs], openai-whisper, kokoro, flask/uvicorn, paramiko, docker SDK, boto3, exchangelib, imapclient. Pe gazdă: A0 Launcher (Electron) și A0 CLI (uv + CPython 3.12 + Python Playwright, care folosește un Chromium deja instalat).
- **Facturare:** Completare: configurația include și providerul „Agent Zero API” (a0_venice, api_base https://llm.agent-zero.ai/v1, catalog de modele Venice). Este un serviciu găzduit separat, în afara conturilor proprietarului, deci refuzat ca serviciu nou. La login, orchestratorul oferă `claude auth login --claudeai` (abonament), dar și `--console` și ANTHROPIC_API_KEY (facturare API). Ghidul de instalare se referă explicit la ChatGPT Plus, care nu include credite API. Restul clasificării este confirmat: LiteLLM/chei API BLOCKED, codex_oauth REJECT, extra-usage BLOCKED, apiBillingRisk high.
- **Complexitate operațională:** Precizare: parola RFC ține de RFC Parameters (doar instanțe locale) și de setup-ul hibrid de dezvoltare, nu de o instalare obișnuită. Restul este confirmat: port 80 mapat (docker run -p 80:80), UI Login/Password, Root Password pentru SSH și container nou la trecerea v1.20 → v2.0.
- **Suprapunere nativă OpenAI:** (5) openai.dots: status ELIGIBILITY_UNKNOWN, nu PLAN_RESTRICTED. Recapitularea îl listează pentru Pro, Business Premium și Enterprise, iar planul contului („prolite”, raportat de V1) nu este verificat în V2. Pagina help.openai.com despre nivelurile Pro a răspuns HTTP 403, deci corespondența „prolite” → Pro nu poate fi confirmată.
- **Suprapunere nativă Anthropic:** (1) status NEEDS_SETUP, nu AVAILABLE. Computer use în Claude Desktop este research preview pe macOS și Windows, doar pentru Pro/Max (nu Team/Enterprise), și se activează din Settings > General (pe Windows, cu efect imediat). Toggle-ul nu este verificat, iar uneltele de control desktop nu sunt active în această sesiune. Nivelurile: browserele și platformele de trading sunt view-only, terminalele și IDE-urile click-only. Se adaugă anthropic.claude_cowork: sesiunile Cowork locale rulează codul într-o VM izolată (Hyper-V pe Windows), iar cele cloud într-un sandbox temporar izolat. Asta acoperă nativ izolarea pentru cod și fișiere, fără desktop grafic documentat.
- **Valoare unică:** Punctul (1) trebuie restrâns. Izolarea pentru cod și fișiere există deja nativ: Cowork (VM locală Hyper-V), sesiunile cloud Claude și Codex cloud. Pentru dots, eligibilitatea este necunoscută, nu restricționată dovedit. Unic rămâne doar un desktop grafic Linux (XFCE) izolat, condus de agent. Asta întărește decizia REFERENCE.
- **Decizie:** **REFERENCE** — Se aplică regula de 80%. Nevoia de „computer worker” a proprietarului e deja acoperită nativ, pe abonamente. Pe partea Anthropic (Max verificat): computer use în Claude Desktop pe Windows, Claude in Chrome / `claude --chrome`, panoul Browser din Desktop și `claude -p` pentru terminal și cod. Pe partea OpenAI: Codex app-server/CLI pentru terminal și cod, Computer Use și browserul integrat din ChatGPT desktop, extensia @Chrome. Ce lipsește cu adevărat e mic: verificări deterministe, fără model, ale UI-ului Hub și dovezi de audit. Se acoperă cu Playwright, fără un sistem mare. Agent Zero ca runtime ar încălca principiile Hub-ului. Ar deveni un al doilea plan de control (tiparul OpenClaw retras). Ruta lui pentru planul ChatGPT imită Codex CLI printr-un endpoint nedocumentat, deci REJECT pentru componenta _oauth/codex_oauth. Ruta Claude anunțată este extra usage plătit, iar cheile API LiteLLM sunt refuzate. Orchestratorul folosește implicit bypassPermissions și --dangerously-bypass-approvals-and-sandbox. Browserul este construit pentru ocolirea detecției anti-bot. Proiectul are CVE-uri recente de RCE și path traversal și o stivă Docker/Python grea. Rămâne o referință valoroasă de design (contractul computer_use_remote, UIA, lease/re-armare, Time Travel, Annotate) care se poate cita cu atribuire MIT.
- **Ownership propus:** Agent Zero nu se instalează, nu se clonează și nu rulează. Hub-ul (hub.local, modulul runtime/computer) deține un ComputerRuntime mic: (a) un worker Playwright în Node, fără model, limitat implicit la 127.0.0.1/localhost, cu context izolat, trace și capturi salvate ca dovezi de audit; (b) computer use pe desktop rămâne nativ (Claude Desktop computer use, Codex Computer Use) în regim ASSISTED: Hub-ul pregătește instrucțiunea și criteriile de verificare, proprietarul pornește sesiunea în aplicația vendorului, iar Hub-ul înregistrează rezultatul; (c) fără DesktopBridge propriu până apare o nevoie reală neacoperită. Dacă apare, contractul se inspiră din computer_use_remote, cu mențiune în .ifrim/THIRD_PARTY_NOTICES.md. Catalin decide orice instalare (pachet npm, binare de browser) și orice activare de computer use nativ.

**Puncte forte**

- Izolare completă într-un container Docker: desktop XFCE real, Chromium, LibreOffice și SearXNG. Agentul lucrează pe un calculator separat de unică folosință, fără să atingă desktopul proprietarului.
- Browserul citește pagina ca referințe numerotate ([link 1], [button 2]) și are un vocabular larg de acțiuni: navigate, click, type, upload, evaluate, keyboard, clipboard, multi. Păstrează capturi de ecran per pas în istoric, utile ca dovezi.
- Annotate mode (Inspect / Change / Lift / Comment pe elemente DOM): un tipar bun pentru review de UI cu instrucțiuni legate direct de element.
- Puntea A0 CLI către gazdă separă permisiunile: F3 dă citire/scriere pe fișierele gazdei, F4 dă execuție de cod. Computer use pe gazdă se activează doar pe sesiune/lease (/computer-use on) și cere re-armare (COMPUTER_USE_REARM_REQUIRED).
- Pe Windows, computer use pe gazdă se bazează pe UI Automation: list_windows → get_window_state → element_action cu dispatch background/foreground. Regulile de verificare sunt solide: acțiunile contează ca „încercări” până la o captură nouă, iar tastarea e considerată reușită doar cu focus_verified=true.
- Time Travel oferă snapshot, diff, travel și revert pentru spațiul de lucru /a0/usr, ca strat de recuperare peste Git.
- Proiectele izolează memoria, secretele, cunoașterea, repo-urile și preseturile de model. Memoria FAISS are zonele main, fragments, solutions și skills.
- Multi-agent ierarhic (subordonați cu context propriu), MCP ca client și server (fastmcp/mcp), A2A (fasta2a), peste 100 de pluginuri comunitare. Prompturile și uneltele sunt complet inspectabile.
- Pluginul _orchestrator ține un registru de adaptoare pentru CLI-urile oficiale (codex, claude, gemini, cursor, opencode, grok, hermes), rulate headless prin puntea gazdei. Este același tipar ca adaptoarele V2 ale Hub-ului.
- Pe Windows funcționează prin Docker Desktop, A0 Launcher (x64/ARM64) și A0 CLI instalat din PowerShell. Pe această mașină există deja Docker 29.4.3 și WSL (verificat doar cu --version).

**Puncte slabe**

- Ar fi un al doilea plan de control complet: chat, memorie, proiecte, programări, secrete, pluginuri, integrări Telegram/WhatsApp/e-mail. Ar dubla și ar concura Hub-ul canonic, adică exact tiparul OpenClaw pe care V2 l-a retras.
- Stiva este grea: Python 3.12 în Docker, cu XFCE, LibreOffice, SearXNG, Whisper, Kokoro TTS, unstructured, sentence-transformers, nginx, supervisor, SSH și self-update. Nu se potrivește lângă Hub-ul Node 24 local.
- Facturarea de bază merge prin LiteLLM și chei API (OpenAI, Anthropic, OpenRouter etc.). Ghidul de instalare spune explicit că abonamentul ChatGPT nu include credite API.
- Ruta „Use Your OpenAI Codex Plan” (_oauth / codex_oauth) nu este un client oficial. Reutilizează client_id-ul public al Codex CLI și se prezintă drept Codex CLI (originator codex_cli_rs, User-Agent codex-cli, codex_version 0.155.1). Apelează endpointul nedocumentat chatgpt.com/backend-api/codex și păstrează tokenuri echivalente unei parole în auth.json, în container.
- Pentru Claude, README-ul anunță doar o integrare viitoare „through extra-usage”, adică utilizare suplimentară plătită. Orchestratorul oferă și ANTHROPIC_API_KEY sau claude auth login --console, deci facturare API. Toate trei sunt refuzate de INCLUDED_SUBSCRIPTION_ONLY.
- Valorile implicite ale orchestratorului sunt nesigure: claude permission_mode=bypassPermissions, codex exec --dangerously-bypass-approvals-and-sandbox, grok always_approve, hermes yolo, cursor force. Sunt exact flagurile interzise în adaptoarele V2.
- Browserul intern folosește patchright („Undetected version of Playwright”, Apache-2.0) și pyreqwest-impersonate. Ambele sunt orientate spre ocolirea detecției anti-bot, ceea ce contravine regulilor Hub-ului.
- Are istoric de vulnerabilități. Verificate: CVE-2026-30624 (RCE prin configurația MCP externă, v0.9.8, CVSS 8,6) și CVE-2026-47118 (path traversal neautentificat pe endpointul de imagini, înainte de v1.14). Alte două (CVE-2026-4307 path traversal, CVE-2026-4308 SSRF) apar doar în rezultate de căutare, fără pagini citite.
- Instalatorul și A0 CLI se instalează prin `irm … \| iex` sau `curl … \| sh`, adică execuție directă a unui script descărcat. Browserul gazdei se controlează prin CDP remote debugging, care dă control complet asupra sesiunii de browser.
- Computer use pe gazdă este beta. Hub-ul nu are niciun mod oficial de a-l conduce programatic, decât printr-o instanță Agent Zero care rulează.

**Componente reutilizabile**

- Contractul uneltei computer_use_remote (start_session, status, capture, list_windows, get_window_state, element_action, click, type, key, scroll, stop_session) și regulile de verificare vizuală. Poate servi ca model pentru un eventual contract DesktopBridge al Hub-ului, doar ca referință, cu atribuire MIT.
- Tiparul Windows UI Automation: țintire structurală prin element_index și dispatch background, înaintea clicurilor pe coordonate normalizate.
- Activarea computer use pe durata unei sesiuni/lease, cu re-armare obligatorie. Se potrivește cu modelul de grant-uri al Hub-ului.
- Separarea permisiunilor punții gazdei în fișiere RW (F3) și execuție de cod (F4), fiecare comutată explicit.
- Modelul de citire a paginii cu referințe numerotate, plus capturi per pas păstrate în istoric pentru audit.
- Annotate mode (Inspect / Change / Lift / Comment) ca idee de UX pentru review de UI în Hub.
- Time Travel (snapshot / diff / revert al spațiului agentului) ca idee pentru rollback-ul misiunilor, complementar Git-ului și backup-ului Hub.
- Registrul de adaptoare _orchestrator (binary, detectare auth, smoke prompt, ecran de stare), de comparat cu adaptoarele V2. Nu se preiau valorile implicite periculoase.
- Catalogul usage_plans (metadate de plan și facturare per furnizor, cu link-uri oficiale), ca idee pentru afișarea contextului de abonament în Hub.
- Contractul computer_use_remote conține și acțiunea move. Lista completă: start_session, status, capture, list_windows, get_window_state, element_action, move, click, scroll, key, type, stop_session. Skill-ul Windows mai documentează uia_snapshot și uia_action. Toate se preiau doar ca referință, cu atribuire MIT.

**Puncte forte**

- Stări vizuale explicite ale agentului (IDLE / THINKING / RESPONDING) într-un indicator ambiental unic, ușor de citit de la distanță

- Responsive, gesturi touch, PWA instalabilă (manifest + service worker)

Cheia este opțională, iar fără ea SDK-ul (care rulează binarul Claude Code și încarcă automat configurația din ~/.claude/) poate prelua login-ul local claude.ai. Documentația Agent SDK spune că aceasta este o rută nesancționată pentru produse terțe. Varianta nativă (Claude Code headless pe Max, deja în adaptorul V2 cu mediu controlat) rămâne superioară. Agent view este research preview, iar sesiunile background consumă din abonament.
- **Valoare unică:** După suprapunerile native rămân: (1) inferența locală/offline pe Ollama sau llama.cpp, fără abonament și fără API; (2) telemetria de energie, FLOPs și latență și benchmark-urile; (3) învățarea din trace-uri (routing învățat, DSPy/GEPA) și pattern-urile de colaborare local-cloud; (4) o arhitectură de referință Apache-2.0 bine documentată pentru registry, EventBus, trace, guardrails, aprobări și audit. Pentru Hub are valoare imediată doar (4). Punctele (1)–(3) depășesc politica actuală și cer o decizie separată a owner-ului (inferența locală nu este reglementată explicit de INCLUDED_SUBSCRIPTION_ONLY).
- **Decizie:** **REFERENCE** — REFERENCE, ca referință de arhitectură. NU ADAPT și NU INTEGRATE, pentru că: (1) stack-ul Python + Rust nu se potrivește cu Hub-ul Node 24 / React; (2) este un control plane complet concurent, iar integrarea ar rupe principiul „Hub = singurul control plane canonic, fără lock-in”; (3) suprafețele care ar acoperi nevoile Hub-ului (motoare cloud, ClaudeCodeAgent, STT/TTS cloud, Tavily) cer chei API plătite, blocate de INCLUDED_SUBSCRIPTION_ONLY, în timp ce echivalentele native pe abonament (Codex CLI/app-server, Claude Code pe Max) sunt deja integrate în V2; (4) analytics externe sunt pornite implicit, iar installer-ul irm\|iex, Ollama și scheduled task-ul încalcă BUILD_SAFE; (5) aprobările nu au autorizare, iar sandbox-ul este oprit implicit. Nu este REJECT, pentru că licența Apache-2.0 și design-ul EventBus, Trace, guardrails, PendingAction și bind pe loopback oferă pattern-uri valoroase de reimplementat în Node. Nu se preiau identitatea sau branding-ul „Jarvis”, vocile sau modelele TTS/STT și nici modelele descărcate.
- **Ownership propus:** Owner decizie: Catalin. Custode tehnic: rolul de arhitectură și securitate al Hub (Opus, conform politicii de modele din proiect). Referința se păstrează în .ifrim/V2_ARCHITECTURE.md sau .ifrim/REBUILD_DECISIONS.md, cu link și data commit-ului (2026-09-29). Pattern-urile selectate (taxonomie de evenimente, trace, guardrails, PendingAction cu autorizare, capability policy) se reimplementează în v2/server/domain, cu teste în `npm run test:v2`. Orice fragment adaptat primește atribuire Apache-2.0 și NOTICE în .ifrim/THIRD_PARTY_NOTICES.md. Un eventual motor local (Ollama/llama.cpp) este o decizie separată, cu aprobare explicită, evaluat izolat (VM), cu [analytics] enabled = false înainte de prima rulare și fără installer irm\|iex pe mașina principală. Reevaluare trimestrială sau la o nouă versiune majoră.

**Puncte forte**

- Arhitectură modulară bine documentată: registry pe bază de decoratori (RegistryBase: Model/Engine/Memory/Agent/Tool/RouterPolicy/Channel), contracte ABC clare (InferenceEngine: generate/stream/list_models/health; BaseAgent.run → AgentResult)
- EventBus thread-safe cu taxonomie de evenimente utilă: INFERENCE_START/END, TOOL_CALL_START/END, MEMORY_STORE/RETRIEVE, AGENT_TURN_START/END, TRACE_STEP/COMPLETE, SECURITY_SCAN/ALERT/BLOCK, scheduler_task_start/end
- Trace complet pentru fiecare interacțiune (routing, retrieval, inferență, tool calls, răspuns); audit append-only în SQLite pentru evenimentele de securitate
- Guardrails cu moduri WARN / REDACT / BLOCK, SecretScanner și PIIScanner; FileReadTool apelează is_sensitive_file() (.env, *.pem, id_rsa, credentials.*)
- Model de aprobări PendingAction (id, tip, descriere, payload, permission tier, status, created/expires_at) cu endpoint-uri approve/deny și expirare automată
- Server legat implicit pe 127.0.0.1:8000; refuză să pornească pe interfețe non-loopback fără OPENJARVIS_API_KEY; comparare constant-time a cheii
- Capability policies cu profiluri personal / shared / server (default_deny pentru shared/server)
- Scheduler cron / interval / once cu store SQLite și run log; memorie SQLite FTS5 implicită, cu FAISS/ColBERT/BM25/hybrid opționale
- Voce locală posibilă: faster-whisper (STT), Kokoro (TTS), înregistrare cu detecție de liniște (RMS, 1,5 s liniște, 5 s timeout)
- Telemetrie locală per inferență (latență, TTFT, tokeni, cost estimat, energie) în ~/.openjarvis/telemetry.db
- Suport Windows nativ activ (install.ps1, scheduled task opțional pe loopback, fixuri recente pentru daemon)

**Puncte slabe**

- Stack Python 3.10–3.13 + extensie Rust + frontend Node, deci nu se potrivește cu Hub-ul Node 24 / React; Python 3.14 nu este suportat
- Este un control plane complet concurent (agenți, scheduler, memorie, aprobări, server, canale), iar adoptarea lui ar încălca principiul „Hub = singurul control plane canonic”
- Motoarele cloud cer OPENAI_API_KEY / ANTHROPIC_API_KEY (facturare API); ClaudeCodeAgent rulează @anthropic-ai/claude-agent-sdk cu ANTHROPIC_API_KEY, nu cu login-ul abonamentului Max
- Analytics externe PornITE IMPLICIT (AnalyticsConfig.enabled = True), trimise către o instanță PostHog pe un host de tip IP (sslip.io); dezactivarea se face manual prin [analytics] enabled = false
- Endpoint-urile de aprobare nu au autorizare vizibilă; documentația spune că confirmarea tool-urilor nu este încă aplicată universal, deși config-ul are enforce_tool_confirmation = True
- Sandbox dezactivat implicit; modul de securitate implicit din TOML-ul generat este warn (nu redact/block); scanarea output-ului la streaming nu poate retrage tokenii deja livrați
- Dependențe core grele sau neobișnuite: datasets, nvidia-ml-py, posthog, python-telegram-bot, openai
- Installer bazat pe `irm … \| iex`, instalare silențioasă Ollama (~150 MB) și model (~1,1–15 GB), modificări în User PATH, scheduled task la logon
- Fără wake word; bucla de voce nu are barge-in în voice_io
- Canal WhatsApp prin Baileys (protocol WhatsApp Web neoficial), risc de conformitate
- Documentație inconsecventă (Windows, telemetrie); API-uri de cercetare care se pot schimba
- Corecturi de formulare: „PornITE IMPLICIT” devine „pornite implicit”; „confirmarea tool-urilor nu este încă aplicată universal” devine „enforce_tool_confirmation nu este aplicat în prezent (conform documentației)”; „Documentație inconsecventă (Windows, telemetrie)” devine „Documentație inconsecventă (telemetrie: PostHog Cloud US în docs vs host sslip.io în cod, pagina user-guide fără PostHog; Node 18+ vs 22+; versiunea 0.1.0 în exemple)”. Windows nativ este documentat consecvent în README, install.md și windows-native.md.

**Componente reutilizabile**

- Pattern-uri de reimplementat în Node în v2/server (fără copiere de cod; dacă se adaptează vreun fragment, atribuire Apache-2.0 + NOTICE în THIRD_PARTY_NOTICES):
- Taxonomia EventBus (INFERENCE_*, TOOL_CALL_*, MEMORY_*, AGENT_TURN_*, TRACE_*, SECURITY_SCAN/ALERT/BLOCK, scheduler_task_*) mapată pe events.seq din Hub
- Obiect Trace per misiune sau turn (routing → context/memorie → apel model → tool calls → rezultat), pentru audit și reluare
- Guardrails cu moduri WARN / REDACT / BLOCK și scanere de secrete și PII aplicate înainte ca prompturile să ajungă la Codex sau Claude Code; deny-list de fișiere sensibile la nivel de tool
- Model PendingAction cu permission tier, expires_at și expire_stale, completat cu autorizarea aprobatorului, care la OpenJarvis lipsește
- Capability policies pe profiluri, cu default_deny pentru orice profil partajat sau server
- Regula de pornire: bind pe loopback implicit, refuz de pornire pe non-loopback fără cheie, comparare constant-time
- Registry cu decoratori pentru adaptoare (Codex app-server, Claude headless), canale și politici de routing
- Scheduler cron / interval / once cu store SQLite și run log (Hub are deja scheduler; comparați semantica)
- Telemetrie locală per turn (latență, TTFT, tokeni, rate-limit) în SQLite, cu costul setat la 0 pentru abonamente
- Schema de analytics cu whitelist de evenimente și redaction (evenimentele necunoscute sunt aruncate), ca model pentru diagnosticul local, niciodată trimis extern
- Idei de routing local/cloud (după complexitate, advisor, decompose-and-execute de tip Minions), traduse la Hub ca rutare între suprafețe de abonament (Codex vs Claude Code), nu spre API plătit
- Completare: taxonomia EventType este mai bogată decât în evaluare și merită mapată pe events.seq. Pe lângă cele listate, include: CAPABILITY_DENIED, TAINT_VIOLATION, RATE_LIMITED, LOOP_GUARD_TRIGGERED, TOOL_TIMEOUT, AGENT_BUDGET_EXCEEDED, AGENT_STALL_DETECTED, SESSION_START/END, WORKFLOW_START/NODE_START/NODE_END/END, SKILL_EXECUTE_START/END și A2A_TASK_RECEIVED/COMPLETED. EventBus-ul este protejat cu threading.Lock. Pentru PendingAction, Hub-ul trebuie să adauge ce lipsește la OpenJarvis: autorizarea aprobatorului, chiar și pe loopback.
